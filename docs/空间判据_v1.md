## 结论三句话

1. **「双峰值 Pareto」不是两个并列轴。** Pareto 的两轴是 **时间** 与 **`peak_tracemalloc_mb`（堆峰值）**；
   **`peak_rss_mb` 是资源上限门禁，不是改进轴** —— D 现在的用法（拿 `peak_tm` 判改善、RSS 只做门禁）**是对的，不用改**。
2. **RSS 不可分辨时：门禁自动跳过，既不待复测也不排除。**
   「待复测」只留给**测量异常**（`status != ok`、峰值缺值），不用于「数值太小」。
3. **`status=ok` 但没拿到峰值：有明确标记**，三态 `measured / unmeasurable / unmeasured`，由 `eval/space.py` 给，D 直接读。

## 一、为什么 RSS 不能当奖励轴

| 事实 | 数据 |
|---|---|
| RSS 含解释器基线 | 本机空载 **20.5 MB**，全部题目都在 20–21 MB |
| RSS 原生题不可分辨 | **0/19** 达到「基线+5 MB」；差值 <0.1 MB |
| RSS 采样粒度 | `psutil` 5 ms 轮询，短用例（0.02–0.2 ms）**根本采不到峰值** |
| 升档后才可分辨 | 输入放大到 2e5 元素：6/10 题 delta 达 15–55 MB |

把不可分辨的量放进接受判据 = **让噪声决定接受/拒绝**。这正是我们这周修掉的那类 bug
（剖析不对称导致 0 采纳、`mem_mbs` 假 100%），不能换个名字再犯一次。

## 二、三态标记（D 缺的就是这一块）

`space_status(mem, rss_baseline_mb)` 返回：

| 字段 | 取值 | 含义 / D 该怎么做 |
|---|---|---|
| `peak_tm_status` | `measured` | `≥ 0.05 MB`，**参与 Pareto** |
| | `unmeasurable` | `< 0.05 MB`，**空间维度整体退出**，退化为「只比时间」，报告标 `space_unmeasurable` |
| | `unmeasured` | 值为 `None`（内存轮次没跑成 / tracemalloc 不可用），**不参与比较**，标 `space_unmeasured` |
| `rss_status` | `gated` | 基线 − 空载 ≥ 5 MB 且差值大于噪声 → **门禁生效** |
| | `indistinguishable` | 差值在噪声内 → **门禁自动跳过，不否决任何候选** |
| | `unavailable` | `None`（psutil 缺失）→ 跳过 |

**关键**：`unmeasurable` 与 `unmeasured` 是两件事——
前者是「这题太小，量不出」，后者是「这次没量到」。前者永远不该变成 `n/a` 挂在表里，
后者必须重测或标缺。

## 三、接受规则（`pareto_accept`）

```
accept  ⇔  (时间显著改善 或 堆峰值显著改善)
        且 没有任何可测轴显著变差
        且 RSS 门禁通过（仅在 gated 时生效）
```

| 阈值 | 默认 | 含义 |
|---|---|---|
| `TIME_REL_GAIN` | 1% | 时间改善至少 1%（低于噪声不算改善） |
| `SPACE_REL_GAIN` / `SPACE_ABS_GAIN_MB` | 10% / 0.005 MB | 堆峰值改善至少 10%（或绝对 0.005 MB） |
| `PEAK_TM_MIN_MB` | 0.05 MB | 低于此值：空间不可测（与题库筛选 H1 同口径） |
| `RSS_DELTA_MIN_MB` | 5 MB | RSS 门禁生效的最小可分辨量 |
| `RSS_GATE_REL` / `RSS_GATE_ABS_MB` | 10% / +1 MB | 门禁上限 = `max(base×1.1, base+1MB)` |

**Pareto 的硬边界**：时间改善但堆峰值显著变差 → **reject**（不允许拿空间换时间）。这条是老师第 3 条的核心。

## 五、和「待复测」的关系

| 情形 | 处理 |
|---|---|
| `status != ok` | **待复测**（测量失败） |
| 峰值 `None` | `unmeasured` → 重测一次；仍缺则标缺，**不阻塞整批** |
| `peak_tm < 0.05 MB` | `unmeasurable` → **不是等待**，是「这题量不出来」，直接按时间判定 |
| RSS 不可分辨 | 门禁跳过，**不是等待** |

D 现在把空间决策停在「待复测」——**只有在上一行「`status != ok` / 峰值 `None`」两种情况下才是对的**，
其余情况应该立刻给出判定。否则实验会卡在等待里出不来。

## 附：自测覆盖（`python eval/space.py`）

1. 时间+空间都改善 → accept
2. 时间改善、堆峰值变差 → **reject**（Pareto 硬边界）
3. 小题空间不可测 → 只看时间 + `space_unmeasurable`
4. RSS 不可分辨 → 门禁跳过（不否决）
5. RSS 可分辨且明显变胖 → 门禁否决
6. 缺峰值 → `unmeasured` 只降级不否决；`status!=ok` → `incomparable`
