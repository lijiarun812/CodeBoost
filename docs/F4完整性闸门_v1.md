> 术语：**F0–F4 是五档反馈方式**，F4 完整版的仓库方法名是 `ours`（见 `空间判据_v1_1.md` 附录）。

## 一、本期 F4 的范围（建议批准，附三条边界）

| 本期**做** | 本期**不做**（不得宣称） |
|---|---|
| 热点行的**逐行时间占比** | **逐行内存归因**（"这行占多少内存"） |
| 热点行**周边代码**（±N 行 + 所在函数/循环链） | 完整调用链（跨函数/跨文件深度） |
| **程序级**空间信息（`peak_tracemalloc_mb` / `peak_rss_mb`） | 规模变量（n、数据规模随行的变化） |

三条边界（写进提示词与文档，避免答辩被问穿）：

1. **逐行时间是插桩后的**：只能给「占已剖析行时间之和的百分比」，不得写成「占总运行时间」，
   `case_ms < 2 ms` 时**只给执行次数**（不给占比，分母本身是噪声）。
2. **程序级峰值 ≠ 逐行归因**：反馈里必须写「程序级」三个字；不得出现「这一行耗了 X MB」这类表述。
3. **空间信息在原生题上多半没信号**：实测 EffiBench 原生题 `peak_rss` 可分辨 **0/19**、
   `peak_tracemalloc` 中位 0.0017 MB。所以 F4 必须允许把空间字段写成
   `n/a（本题空间不可分辨）`，**不许为了凑满反馈而填数字**。

## 二、闸门五项（全过才允许写 `ours`）

| # | 检查项 | 通过判据 | 不通过时 |
|---|---|---|---|
| **G1** | 反馈完整性标记 | `diagnostics` 里同时存在 `hotspot_mode`、`case_ms`、`profiler_overhead_ratio`、`space_status` 四个键，且都不为 `None` | 不写 Result，`degrade_reason` 按目标档位填，`can_write_result=False` |
| **G2** | 占比口径 | 反馈文案里逐行数字是**百分比**，且注明分母 = 「本次已剖析行时间之和」；`case_ms < 2` 时反馈里**没有任何毫秒或百分比** | 同 G1 |
| **G3** | 空间字段诚实 | 空间值来自 `Result.mem`（程序级），且当 `space_status != "measured"` 时写 `n/a（空间不可分辨）` | 同 G1 |
| **G4** | 诊断不改状态 | 行级诊断失败（`timeout`/`code_error`/`missing_dependency`/`line_mismatch`）只出现在 `diagnostics`，**`Result.status` 与 harness 一致** | 同 G1（必须修代码） |
| **G5** | 与 F3 可区分 | 同一题、同一份代码，F4 的提示词与 F3 的提示词**不同**（`hotspot_mode` 不同 或 反馈含周边代码），并有离线对照留档 | 视为「F4 退化成 F3」，不写 `ours` |

**只有 G1–G5 全过，且该题 `can_write_result` 为真，才允许把 `method` 写 `ours`。**
任何一项不过 → 写实际生效档位（`f3`/`f2`/`f1`）+ `degrade_reason`，**不要**用 `ours` 占位。
