## 一、总体结构

期末拆成两条线，接口先冻结再并行：

```
                     ┌── 复现线（2 人）：论文协议复现 + 模型矩阵 + 论断审计
eval/schema.md ──────┤
（M0 冻结）          └── 优化线（3 人）：数据集/反馈/空间三个方向，共用同一 harness
```

- **共享层** `eval/`：测量与数据基础设施，只由成员 A 维护，其他人只读调用。任何人改测量口径都要走回归测试。
- **复现线** `perfcodegen/`：严格按论文协议跑，产出可对照论文表的数字。
- **优化线** `optimize/`：在中期实验包基础上重写反馈与目标函数，产出 Ours v2。

## 四、协作规则（避免返工）

1. **接口冻结**：M0 只做一件事——`eval/schema.md` 定死 Task/Result 字段。之后谁改字段谁负责迁移全部调用方。
2. **只读共享层**：`eval/` 由 A 独占修改，其他人提 issue 或 PR，必须跑通 golden test 才能合并。
3. **分支与产物**：`repro/*`、`opt/*` 两条分支线；结果统一落 `results/<track>/<dataset>/<model>/<run_id>.json`。
4. **实验必须带 manifest**：模型版本、日期、temperature、seed、数据集哈希、harness commit，缺一项不进汇总。
5. **每次实验先报失败率**：超时率、改崩率、API 失败率三项先看，再看加速比。
6. **每周一次 30 分钟对齐**：只看三张表（题库状态、失败率、主结果），不做进度汇报。
