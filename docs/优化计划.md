# 优化计划（Next Steps）

在现有「EffiLearner 简化复现」的基础上，结合 PerfCodeGen 的执行反馈与 EffiBench 指标，
把复现做扎实、把优化做出来。按依赖顺序推进。

## 一、复现加固（地基，优先）

| 任务 | 说明 | 负责人 |
|---|---|---|
| 内存测量口径修复 | 现有 `mem_mbs` 用「RSS 增量积分」，最终版经分配器预热后 RSS 不增长 → 积分归零（约 22–28 题/模型）。改为**绝对 RSS 积分 / 归一化**口径，消除“假 100%” | 组长 + A |
| 脚手架补全 | 数据集部分题目缺 `build_tree/decode_tree`、`ListNode/TreeNode` 构造，导致失败。补齐辅助函数 | A |
| 失败复测 | 断言失败 / SyntaxError 的题目做代码提取增强与重跑 | A |
| 结果表对齐 | 复现结果与论文表 1/2 做对照，标注口径差异 | A + 组长 |

## 二、指标对齐（让结果可比）

| 任务 | 说明 | 负责人 |
|---|---|---|
| 效率指标实现 | 实现 PerfCodeGen 的 **%Opt / %Correct / Speedup / Best@k**，替换当前“下降%”口径 | 组长 + C |
| 消融对比 | 对比 overhead 提示 / 最耗时单测反馈 / 普通优化三种策略 | C |

## 三、优化实现（结合 PerfCodeGen）

| 任务 | 说明 | 负责人 |
|---|---|---|
| 正确性精炼（§2.1） | 用**失败单测反馈 + plan/refine** 闭环，提高 %Correct | B |
| 性能精炼（§2.2） | 定位**最耗时单测**作为优化信号；配合 Best@k 多采样择优 | C |
| 数据与评测 | 接入 EffiBench / HumanEval / MBPP，统一评测脚本与 README | D |

## 四、总结与汇报

| 任务 | 说明 | 负责人 |
|---|---|---|
| 总结与反思 | 结论、局限（模型/规模/测量差异）、联系课程知识（提示工程 / RAG / 微调 / 评估） | D |
| PPT 与答辩 | PPT 制作；答辩**全员一起回答老师问题**，组长主讲 PPT 并回答基础问题 | 全员 |

## 依赖与里程碑

1. **先**修测量口径与脚手架 → 之后所有优化对比才有可比基准。
2. **再**做指标对齐 + 正确性/性能优化（B、C 并行，用统一评测）。
3. **最后**汇总数据、写总结、做 PPT 与彩排。

## 已知风险

- 模型、数据规模与论文不同 → 只能做「简化复现」，结论需注明。
- 失败率 13–21% → 部分题目需正确性精炼或多采样兜底。
- API 成本/耗时 → 优先用 `deepseek-flash` 等快而省的模型做迭代。
