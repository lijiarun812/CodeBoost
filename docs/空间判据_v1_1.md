## 一、v1 的四个错误（C 核出，全部认）

| # | v1 的错误 | v1.1 的改法 |
|---|---|---|
| 1 | 读顶层 `mean_trimmed_ms`，而 Result 是 **`time.mean_trimmed_ms`** | `time_ms()` 读 `time.mean_trimmed_ms`；扁平结构只保留**向后兼容**（`measure_code()` 的中间产物），不是正式路径 |
| 2 | 峰值 `None`（unmeasured）时会返回 `accept` | 改成 **`retest`**：峰值缺值 → 重测一次；重测用完才按时间判定并标降级 |
| 3 | 基线可测、候选降到分辨率下限以下时，这次改善被丢掉 | 新增 **censoring**：基线 `measured` + 候选 `below_floor` → **判为空间改善**（`censored=True`），只是幅度不可量化 |
| 4 | 没区分「候选 `incorrect`」与「测量异常」 | 新增 **四态决策**，见 §三 |

## 二、v1.1 自己又抓到一个（这个更要紧）

我做真实 Result 端到端测试时发现：**同一份代码重测一次，会被判「时间改善 9.1%」**。
因为 v1 的时间阈值是常数 1%，而 0.63 ms 量级的实测 CV 就有 3%–5%。

**改法：阈值绑到实测噪声** `time_rel_eff = max(TIME_REL_GAIN, 2 × Result.time.cv)`。

- 实测 `cv = 0.045` → 阈值 9%；那么「快 7.9%」判噪声（reject）、「快 20.6%」才算改善（accept）；
- 比较用**严格不等号**：正好等于噪声地板既不算改善也不算变差。

这条不修，D 的接受率会被噪声抬高——和之前「剖析不对称」是同一类错误。

## 三、四态决策（不是三态）

| decision | 触发条件 | 含义 |
|---|---|---|
| `incomparable` | 基线 `status != ok`，或时间缺值且重测已用完 | 没得比，不进比较 |
| `retest` | 候选 `status ∈ {timeout, resource_exceeded, api_failed}`、或 `time.mean_trimmed_ms` 缺、或峰值 `None` | **测量异常**，允许重测（受 `retest_budget` 限制） |
| `reject` | 候选 `incorrect`；或重测后仍异常；或任一可测轴显著变差；或 RSS 门禁未过；或两轴都在噪声内 | 不接受 |
| `accept` | 至少一轴显著改善，且没有可测轴显著变差，且门禁通过 | 接受 |

**`incorrect` 与测量异常的区别（C 的第 4 问）**：

| 情形 | 判什么 | 为什么 |
|---|---|---|
| 候选 `incorrect`（没过测试） | **直接 reject**，不重测 | 代码不合格，重测只会得到同样结果；这是「候选不行」，不是「尺子坏了」 |
| 候选 `timeout` | **retest 一次** | 可能是机器抖动；重测仍 timeout → reject（真的慢） |
| 候选 `resource_exceeded` / `api_failed` | **retest 一次** | 属于环境/测量侧 |
| 峰值 `None` | **retest 一次** | 内存轮次没跑成，属测量缺失 |
| 重测已用完 | 不再给 `retest`，按现有数据判定并在 `reasons` 写明 | 防止无限重测 |

## 四、可测性状态

`peak_tracemalloc_mb`：

| 状态 | 条件 | 参与 Pareto？ |
|---|---|---|
| `measured` | ≥ `0.05 MB` | ✅ |
| `below_floor` | < 0.05 MB（有数值但低于分辨力） | ⚠️ 单独处理：基线可测 + 候选 below_floor → **改善（censored）**；两边都 below_floor → 空间退出 |
| `unmeasured` | `None` | ❌ 触发 `retest` |

`peak_rss_mb`：`gated`（生效）/ `indistinguishable`（差值在噪声内）/ `unavailable`（**没有可核对的当次基线**，或 `peak_rss_mb` 缺值）。

> 后两种都是**门禁跳过、不否决**，但原因不同：`indistinguishable` 是「量了但分不出来」，`unavailable` 是「压根没对照」。后者的处理规则见 [`RSS基线规则_v1.md`](RSS基线规则_v1.md)：
> **不停止整批**、MU 扣基线列一律 `n/a`、报告标「本批 MU 不可用」。

## 五、D 的接入（三行 + 一个循环）

```python
from eval.space import pareto_accept

dec = pareto_accept(base, cand, rss_baseline_mb=20.52, retests_used=0, retest_budget=1)
if dec["decision"] == "retest":
    cand = measure_again()          # 只重测一次
    dec = pareto_accept(base, cand, rss_baseline_mb=20.52, retests_used=1, retest_budget=1)
log(dec["decision"], dec["reasons"])
```

**接口约定**：喂 **`harness.measure_task()` 返回的 Result**（`time.*` / `mem.*` 嵌套结构）。
`measure_code()` 的输出是扁平中间产物，只因为向后兼容才读得动，**不要拿它当正式输入**。
