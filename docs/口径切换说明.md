# 口径切换说明（旧尺子 → 新尺子）

> 一句话：**从今天起，`eval/harness.py` 是唯一测量实现**。中期数字保留但标 `legacy-psutil`，
> 不与新数字进同一张表；需要对照时用「同题同代码重测」的方式另出一列。

---

## 一、新尺子与旧尺子的五处差别

| 维度 | 旧尺子（中期） | 新尺子（eval/harness.py） |
|---|---|---|
| 时间估计量 | 3 次取中位数（逐 assert 分别计时后求和） | **E=12 批，去最高/最低各 2 个取均值**；保留 `raw_ms` |
| 计时环境 | 在同一次执行里同时采内存 | **计时与内存分开测**：计时批次不开 tracemalloc，内存单独一批（tracemalloc 插桩实测能把小用例放慢 3–6 倍） |
| 内存 | psutil RSS 的**时间积分**（MB·s），热身后退化为 0 → “假 100%” | **双口径**：`peak_tracemalloc_mb`（Python 分配峰值）+ `peak_rss_mb`（进程峰值），**不用积分** |
| 超时 | 硬超时（180s / 20s）到点直接杀，判成失败 | **心跳看门狗**（5s 心跳，30s 无心跳才杀）+ 单档预算 + **降档重试**；超时是独立 `status=timeout` |
| 状态 | 只有 ok / 失败（原因混在 error 字符串里） | **五类**：ok / incorrect / timeout / resource_exceeded / api_failed |

## 三、旧口径 vs 新口径：同一份 `final_code` 重测

命令：`python eval/legacy_retest.py --per-model 3`（4 模型 × 3 题，零 API 成本）
产物：`docs/表格_旧口径vs新口径.md` + `docs/legacy_retest.json`

| 项 | 结果 |
|---|---|
| 重测题数 | 12（EffiBench/3、/4、/10 × 4 个模型） |
| 新/旧 比值 | 1.67x – 2.04x，**中位数 1.78x** |
| status | 全部 ok，无 timeout |

**判读**：同一份代码，新尺子量出来比旧尺子大 1.8 倍左右。差异来自三处：函数包装（避免 `exec`
每轮建帧）、E=12 去极值（旧是 3 次中位数）、以及两次测量之间机器状态不同。
**所以新旧数字绝对不可混表**；要比较方法效果，必须在同一把尺子下同时测 baseline 与 candidate。

## 四、为什么不能拿 1.171x 当新基线

`HE/40 = 1.171x` 是**旧尺子**在“输入复用修正后”的加速比（分母是旧口径的 baseline）。
新尺子量的是绝对耗时（本轮 0.0124 ms），要算加速比必须**在同一把尺子下**再测一遍 base 与候选。
规则：旧值只出现在对照列并标 `legacy-psutil`；新表主口径一律 `mean_trimmed_ms`。

## 五、旧结果的处置（不作废中期成绩）

1. `results/repro/repro_*.json`（4 模型 × 100 题）**原地保留**，汇总表标 `legacy-psutil`；
2. 已按第三节抽 12 题做了“同代码双尺子”对照，证明量级差 1.8x；
3. 后续扩到 24–30 题即可关闭此项，**不重新解释方法效果**。

## 六、回归要求

任何人改动 `eval/harness.py` 后必须跑：

```powershell
python eval\harness.py --selftest
python eval\harness.py --dataset humaneval --tasks 31,40,55,59,60,63,96,120,123,130,139,147 --out-dir results/golden
```

判据（见 `eval/schema.md` 第五节）：`protocol_version` 正确、12 题全 ok、CV ≤ 10%、
新值相对本文件第二节浮动 ≤ 20%。任一不满足 = 尺子被改坏，禁止合并。

## 七、已知数据集缺陷（交 B 处理）

| 题 | 现象 | 处理建议 |
|---|---|---|
| `EffiBench/100`（Same Tree） | native 测试块把**列表**直接传给 `isSameTree`（要 `TreeNode`）；生成器里又**没有 `class Solution`**（期望值算不出来） | 该题在 native 与 gen 两档都不可用，建议从冻结题库剔除，或由 B 补 `build_tree()` 转换 |

> harness 行为正确：`status=incorrect` 并保留原始 error；`inputs.py` 检测到生成器缺参考解时会
> 跳过该档（`generator_missing_solution`），绝不“自己考自己”。
