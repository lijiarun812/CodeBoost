## 一、EffiLearner（NeurIPS 2024）

- 文件：`doc/EffiLearner.pdf`
- 位置：**Table 1（第 6 页）** + **§4.3 Main Results 正文**
- 论文全称：*EffiLearner: Enhancing Efficiency of Generated Code via Self-Optimization*
- 数据集：EffiBench；只统计“通过全部测试用例”的代码，所以成功率不影响效率指标。

指标含义（表格列名）：

| 列 | 含义 | 单位 |
|---|---|---|
| ET | Execution Time | s |
| MU | Max memory Usage | MB |
| TMU | Total Memory Usage（内存-时间积分） | MB·s |
| NMU / NTMU | 归一化后的 MU / TMU | — |

我们引用的数字（每个都能在 Table 1 里对上）：

| 模型 | 指标 | 初始 → 优化后 | 论文给的比例 |
|---|---|---|---|
| StarCoder2-15B | ET | 0.93 → 0.12 s | −87.1%（摘要也重复了这组） |
| StarCoder2-15B | TMU | 22.02 → 2.03 MB·s | −90.8% |
| GPT-3.5-Turbo-0301 | ET | 0.36 → 0.28 s | −22.2%（§4.3 正文列出） |
| GPT-3.5-Turbo-0301 | MU | 91.25 → 36.08 MB | −60.5% |
| GPT-3.5-Turbo-0301 | TMU | 157.50 → 12.43 MB·s | −92.1% |
| GPT-4 | ET | 0.31 → 0.28 s | −9.7% |
| GPT-4 | MU | 80.88 → 63.82 MB | −21.1% |
| DeepSeek-6.7B-Instruct | ET | 0.37 → 0.34 s | −8.1% |
| DeepSeek-6.7B-Instruct | TMU | 555.18 → 13.66 MB·s | −97.5% |

**取舍说明**：Table 1 里有几行括号百分比与数值本身对不上（论文排版/口径问题），
我们只保留“表格数值 + 正文/摘要能互相印证”的那几组，避免答辩时被反算质疑。

## 二、PerfCodeGen（FORGE 2025 @ ICSE）

- 文件：`doc/PerfCodeGen.pdf`
- 位置：**摘要（第 1 页）** 给出定性结论；“优于 ground truth 的题目比例”精确数字见
  官方仓库 README 的 *Key result* 段（与论文 Table 2 同源）：
  - GPT-4 在 **HumanEval 约 47%**、**MBPP 约 56%** 的题目上生成出比 ground truth 更快的代码；
  - 不带执行反馈的 GPT-4 基线分别是 39.26% 和 43%。
- 论文主实验设置：`sample_num = 20`，base → 正确性精炼 → 性能精炼三相，指标含 %Correct / %Opt / Speedup / Best@k。

**注意**：47%/56% 是“%Opt（优于 GT 的题目比例）”，不是“加速比”。汇报时不要混用。

## 三、这些数字是怎么取出来的

PDF 没有装 pypdf/pdfminer，所以用 DSH 的 `office_render` 把 PDF 指定页渲染成图片再读：

```
office_render(input="doc/EffiLearner.pdf", pages=[1, 6], dpi=110)
office_render(input="doc/PerfCodeGen.pdf", pages=[1], dpi=100)
```

复现这一步只需要 `office.pdf` 原文件和 `office_render` 工具，不需要联网。
