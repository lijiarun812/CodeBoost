# 实验记录

## 实验 1：EffiLearner 简化复现（100 题 × 3 轮）

### 环境与配置

| 项 | 值 |
|---|---|
| 操作系统 | Windows |
| 运行方式 | `effilearner/effi_repro.py`（OpenAI 兼容 API，纯 Python + psutil 采样） |
| 数据集 | EffiBench 前 100 道 `class Solution` 题 |
| 优化轮数 | 3 |
| 思考模式 | disabled（避免长推理拖慢/空正文） |
| 测量 | 内存-时间积分 `mem_mbs`、执行时间 `exec_time`、RSS 峰值 `peak_mb` |

### 结果

| 模型 | 成功执行 | 时间下降 | 内存下降（可测口径） |
|---|---|---|---|
| deepseek-flash | 87 / 100 | ↓ 27.5% | ↓ 26.4% |
| deepseek-v4-pro | 80 / 100 | ↓ 23.9% | ↓ 24.3% |
| glm-4.6 | 82 / 100 | ↓ 18.3% | ↓ 17.8% |
| qwen3-coder-flash | 79 / 100 | ↓ 15.6% | ↓ 17.6% |

> 原始数据：`results/repro/repro_<model>.json`，汇总：`results/repro/comparison.json`。

### 观察与问题

1. **内存“假 100%”**：每个模型约 22–28 题最终版 RSS 不增长 → 积分归零，导致脚本口径的内存下降被抬高。报告应使用「可测口径」并注明。
2. **失败率 13–21%**：主因是断言失败、SyntaxError、缺 `build_tree/decode_tree`、`ListNode/TreeNode` 构造。
3. **综合最优**：`deepseek-flash`（成功率 87、时间↓27.5%、内存可测↓26.4%，且快而省）。

### 结论

- 复现出 EffiLearner 的核心现象：**带开销反馈的提示能促使模型写出更省内存/时间的代码**。
- 属「简化复现」，与论文在模型、规模、测量方式上存在差异；后续按 `docs/优化计划.md` 加固与优化。
- **口径修正（后补）**：上面的“内存下降”用的是 `mem_mbs`（RSS-时间积分），它近似等于
  「平均常驻内存 × 执行时间」，代码变快就会自动下降，属于时间收益的机械副作用；另有约 30% 的题
  final 积分为 0（采样点不足）。用 `eval/reanalyze_repro.py` 去掉时间因素并剔除零积分题后，
  可测口径为 8.9% / 10.2% / 8.4% / 9.9%（deepseek-flash / v4-pro / glm-4.6 / qwen3-coder-flash）。
  详见 `docs/表格_复现口径对比.md`。

## 实验 2：PerfCodeGen 三相复现（base → 正确性精炼 → 性能精炼）

### 环境与配置

| 项 | 值 |
|---|---|
| 驱动 | `perfcodegen/pcg_repro.py`（只用标准库；psutil 可选，用于采内存） |
| 数据集 | `datasets/sample_humaneval_20.json`（20 题 HumanEval，含中期那 12 题） |
| 提示词 | 官方 `perfcodegen/upstream/templates_chat.json`（论文 §2.1/§2.2 原文模板） |
| 代码清洗 | 官方 `perfcodegen/upstream/sanitize.py` |
| 测量 | `eval/measure.py`：逐 assert 计时、重复放大到 0.25s、多轮取最小值 + MAD |
| 指标 | `eval/metrics.py`：%Correct / Speedup / %Opt / Best@k（k=1,5,10） |

### 结果

| 配置 | 题目数 | 采样 | %Correct | Speedup | %Opt | 备注 |
|---|---|---|---|---|---|---|
| 待填 | | | | | | 跑 `pcg_repro.py` 后把 `results/perfcodegen/<model>/summary.json` 的数字抄进来 |

> 生成方式：`python perfcodegen/pcg_repro.py --provider <厂商> --model <模型> --num 20 --samples 5`，
> 然后 `python eval/make_table.py` 会自动把结果并进“论文 vs 复现”对照表。

### 与论文的差异

见 `perfcodegen/README.md`「与论文的差异」一节（执行层、采样数、用例切分、时间测量、采纳判据）。

### 观察与问题

1. 亚毫秒题（HumanEval/55、63）的噪声与收益同量级，必须 `--min-baseline-ms 1.0` 过滤；
2. 单采样时 Best@5/10 退化为 Best@1，汇报必须标注采样数；
3. 只用 assert 计时，没有做“输入规模放大”，对 O(n²) 类改写的敏感度低于论文。

### 五档反馈粒度（融合实验，结果待填）

| 档位 | 喂给模型的信息 | 对应论文 | 题目数 | 采样 | %Opt(vs GT) | Speedup(vs GT) | %Opt(vs base) | Speedup(vs base) | 反馈字数 |
|---|---|---|---|---|---|---|---|---|---|
| `none` | 不优化 | — | | | | | | | 0 |

| `fusion` | 最慢用例 + per-case 表 + 热点行 | 两篇融合 | | | | | | | ~1000 |

> 两组指标都要报：**vs GT** 是论文口径（但 HumanEval 的 GT 往往很朴素，会出现几十倍加速比，

> 每个档位的结果在 `results/perfcodegen/<model>/summary.json`；逐题的 `evidence_chars` 与
